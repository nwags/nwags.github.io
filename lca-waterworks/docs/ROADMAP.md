# Staged delivery plan

## Immediate milestone — public Power BI companion

Publish a credible educational scenario explorer, not a production rate-setting system. `/lca-waterworks-powerbi/` remains parallel to, not a replacement for, `/lca-waterworks/`.

The user authorized a prepared-scenario edition after the v08 calculation-performance problems. **v09 has now passed the owner-run 33-case native arithmetic check, been published to Service, and received an owner-supplied public embed URL.** The companion embeds that URL with the persistent independence notice. Independent anonymous rendering and interaction checks remain to be completed; see [STATE.md](STATE.md) for exact observed evidence and limitations.

The edition retains three divisions, eleven prepared scenarios, fixed/usage bill components, ten chart families, financing/capital analysis, assumptions, evidence, glossary and synthetic integration specification. It does not expose arbitrary new recalculation or live optimization. Preserve the full v08 development project and JavaScript controls.

The generic builder reads the local public snapshot, checks identity/arithmetic and creates a separate native project. Native project/model data remain outside the public website repository. The [companion README](../../lca-waterworks-powerbi/README.md) records checksums, rebuild instructions, embedding and withdrawal procedures.

### Release and maintenance gates

1. Reconcile every exposed prepared scenario: annual cash continuity, funding identities and default-account bills. Blank results never count as passes. Reference and authoring checks passed for all 33 cases.
2. Run native `Explorer acceptance`: 33 populated rows and residuals within $0.01. The owner's 307.3 ms query and confirmation of all arithmetic passes satisfy this gate for the current snapshot, not future edits.
3. Inspect pages and division/scenario/comparison interactions. Keep friendly captions, balance/flow distinctions and explicit prepared-scenario limits. No claim of arbitrary what-if parity with JavaScript.
4. Measure actual opening/interaction behavior. An isolated query duration does not guarantee all visual or public-Service performance.
5. Keep all underlying model data suitable for unrestricted public access. The owner supplied the Microsoft-generated public iframe; integration preserves its exact URL and Overview default page. Confirm the deployed host and report anonymously and retain both site notices.
6. Revoke the Microsoft public code if withdrawing public access; removing the host iframe alone is insufficient. Never republish confidential ERP/customer information into the publicly exposed model.

### Subsequent work, not first-release blockers

Live Munis integration, comprehensive agreement verification, calibrated stochastic forecasts, full cost-of-service allocation and native optimizer parity remain later milestones. Cosmetic perfection is not required; known misleading figures and unsupported feature claims must be corrected. Do not reinstall temporary diagnostic overrides or label stored scenarios as new optimization results.

## M0 — Define the decision

Establish the horizon, user decisions, source hierarchy, model boundary and website architecture. Preserve independent operation, transparent assumptions and fund separation. Gate: explain what the edition can and cannot analyze.

## M1 — Collect and reconcile evidence

Research budgets, audited history, capital, tariffs, agreements and peer methods. Preserve source units, dates, scope and status. Missing evidence stays explicit; do not invent verified terms.

## M2 — Build and challenge the model

Check ledger identities, bills, constraints and declared optimization limits against independent arithmetic and reference cases. Do not pool funds or silently remove mandatory capital.

## M3 — Build the demonstration

Provide accessible financial views, scenario comparison, evidence drilldowns and integration explanation. Exposed controls must match actual behavior.

## M4 — Explain and review

Maintain methods, glossary, manual and integration guides. Distinguish static checks, native execution, live verification, public-data limitations and stakeholder authority.

## M5 — Publish and hand off

Deploy to the parallel website, verify the served result, record versions and validation, and preserve unrelated portfolio content. Track repository integration, Pages deployment and anonymous Microsoft report verification separately.

## Production pathway

Reconcile complete customer-class history, executed agreements, approved tariffs, restricted balances, covenants and project funding with authorized staff. Introduce governed ERP extracts and operational deployment only as separately approved work.
